S1Info bar with status, no score (2x2)

Templates with a status set and no score get a 4th info-bar cell, so the one-row 3-cell bar becomes a 2x2 grid: Displayed, Due by / Expires, Status. The Status cell shows the chip only (no who/when — that lives on the score layout's full-width row and in Status history). The whole cell is a tap target (chevron) that opens the Change status side sheet.

S2Info bar with score and status (2x2 + full-width status row)

Audit-style templates with a score keep today's 2x2 (Displayed, Due by / Expires, Score). Status gets its own full-width row under it, with the chip, who changed it, and when. The row is tappable (chevron).

S3More Options bottom sheet: “Change status” at the bottom

Tapping the title-bar kebab opens the existing More Options sheet. A new Change status row is added last. It appears only when the list's template has a status set. The row is plain (icon + label only) — no status chip or preview in this sheet (Jim Oct 27). Submit Incomplete List is not blocked by the status rule — incomplete means incomplete.

S4Change status side sheet with history

Same pattern as the multiple-choice side sheet: X plus a bold title, then radio rows. Each row has the color dot and name, and the current status is selected. Status history sits below the options, newest first. If a status was later deleted from the set, history still shows the old name.

S5Submit rule: disabled with a reason, then enabled

SUBMIT ITEMS is enabled only when every item is done and the status is a “can submit from” status (here, only Compliance Approved). When the status is what blocks it, a short reason sits next to the pill.

S6Offline: header shows Offline · Synced at…

A status changed while offline is applied locally right away and syncs like other answers on the next sync. There is no per-status “Waiting to sync” marker under the chip, on the full-width status row, or in Status history (Jim Oct 27). The header still shows Offline · Synced at… (matches the app). Notifications fire only after sync. No per-item sync status.

S7List of lists: status color alternatives

The list column is already crowded (name, due time, count, progress ring, plus red for overdue, yellow for due soon, and blue for selected). Three ways to add status color without adding text. Lists whose template has no status set (Inventory Sheet) show nothing. Decided: always show the status color, including the default In Progress (gray) — people may look for lists still in the default.

S8Submitted lists live in History — status display-only

Submitted lists drop out of All lists / My lists. To reopen one: Back from All lists → History folder (Today / Yesterday / Last 7 days / Custom) → pick the list. On that detail there is no kebab (so no More Options / Change status), and Status under the title bar is display-only — chip only, not tappable, no chevron or lock.

S9All lists kebab → Options bottom sheet

On the main Lists screen (All lists), the title-bar kebab (top-right of the All lists bar — not the blue detail title bar) opens an Options bottom sheet. Today that sheet has Sort & Filter and Language. Sort & Filter is the entry point for list-of-lists filter (Filter by Status in S10–S11). This is a design requirement for the app epic (list-of-lists sort/filter), separate from the per-list More Options sheet in S3.

S10Sort and filter: Filter by Status (no Sort by Status)

No Sort by Status. Different lists can use different status sets; sorting would intermingle sets (Jim Oct 27). Sort Lists stays as today (Due / Display Time / List Name / List Title Asc–Desc only). Under Filter by Lists, below Templates, add a Status row (same style: label + summary). Tapping Status opens the multi-select side sheet (S11). While any Status filter is active, lists whose template has no status set drop out of the view until the filter is reset.

S11Filter by Status multi-select side sheet

Same chrome as Filter by Templates: X to close, search icon, checkbox list. Rows are statuses with color dots (sample set: Costco Compliance Review). Multi-select — a couple checked to demonstrate. Applying returns to Sort and filter with a summary on the Status row (e.g. “2 selected”). While the filter is active, lists with no status set drop out until RESET (same rule as S10).

Prior questions closed Oct 26 (History path + no kebab + display-only status). No open sort/filter questions.

  1. Decided. Accidental taps / confirm: No confirmation. Tap applies the status and closes the sheet (same as multiple choice).
  2. Decided. Who can change (roles): Deferred. All statuses stay selectable for now. Role limits are out of the status-set config; revisit later. Who/when + history are the accountability trail.
  3. Decided. Default status meta: Nothing. No who/when line until someone changes the status.
  4. Decided. Who/when in the 2x2 cell: Dropped — the taller cell felt too heavy. Who/when only on the full-width status row (score layout) and in Status history.
  5. Decided. Submit Incomplete List: Not blocked by the status rule. Incomplete means incomplete.
  6. Decided. Offline wording: Keep “Offline · Synced at…” in the header when offline. Obsolete: “Waiting to sync” (cloud-upload) under the status chip, on the full-width status row, or on Status history — removed; status applies locally offline and syncs like other answers, with no per-status pending UI (Jim Oct 27). No per-item sync status.
  7. Decided. Conflicts: Last sync wins; history and the current status show one truth after sync.
  8. Decided. Submitted lists: Drop out of All lists / My lists. Open via History folder. No kebab / no More Options. Status displays under the title bar and cannot be changed (S8). Obsolete: Locked after submit in More Options; lock-instead-of-chevron; tappable read-only Status sheet.
  9. Decided. List-of-lists dots: Always show the status color, including default In Progress (gray).
  10. Decided. History after a status is deleted: Show the old name as it was (struck + “Removed from set” in S4).
  11. Decided. Lists kebab → Filter by Status: All lists title-bar kebab opens Options (Sort & Filter, Language). Add Filter by Status under Templates, opening a multi-select side sheet like Templates (S9–S11). Obsolete: Sort by Status (Asc/Desc) — dropped because different lists can use different status sets and sorting would intermingle them (Jim Oct 27).
  12. Decided. Status filter · no status set: While any Status filter is active, lists whose template has no status set drop out of All lists / My lists until the filter is reset.
  13. Decided. More Options · no status chip: Change status in the S3 bottom sheet is a plain row (icon + label only). Do not show the current status chip or preview there (Jim Oct 27).
  14. Decided. Status Asc/Desc order: Obsolete. Sort by Status removed; Asc/Desc semantics no longer apply.
